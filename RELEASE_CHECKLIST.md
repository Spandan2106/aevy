# Aevy Release Checklist

Use this checklist before tagging or publishing a release. A checked item means it was actually verified for that release candidate.

## Automated validation

- [ ] Run `python -m unittest discover -s tests -v` from the repository root.
- [ ] Run `python -m aevy --help`.
- [ ] Run `python -m aevy examples/hello.aevy`.
- [ ] Run `python -m aevy examples/modules/main.aevy`.
- [ ] Run `python -m aevy examples/file_io.aevy` and confirm the generated file is in the documented directory.
- [ ] Confirm syntax and runtime errors do not print an unexpected Python traceback.
- [ ] Build and install the package in a clean virtual environment, then run the `aevy` command.

## Language and safety review

- [ ] Test missing modules, repeated imports, nested imports, and circular imports.
- [ ] Test invalid file paths, missing files, invalid argument types, and permission errors where practical.
- [ ] Verify imports and file operations cannot escape the documented base directory.
- [ ] Review all documented built-ins and syntax against the implementation.
- [ ] Check that no credentials, private data, generated bytecode, or local environment files are included.

## Release preparation

- [ ] Update version and release notes.
- [ ] Review README and SPEC.md for accuracy.
- [ ] Verify examples from a clean checkout.
- [ ] Create a Git tag only after all required checks pass.
